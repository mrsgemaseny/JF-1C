# Журнал разработки — JF-1C (ZhanFinance)
Дата: 2026-10-07

## Сессия: Укрепление 2FA (TOTP) и исправление входа для ролей с обязательной 2FA (ADMIN)

### 1. Контекст задачи
- **Проблема**: При сбросе двухфакторной аутентификации у администратора в БД (`two_factor_enabled = false, totp_secret = null`) дальнейший вход блокировался. Бэкенд отвечал требованием 2FA (`requires2FASetup`), однако на фронтенде отсутствовала форма первичной настройки TOTP на этапе логина, а контракт `AuthResponse` не разграничивал ввод кода от первичной настройки. Кроме того, существовала критическая уязвимость обхода 2FA: эндпоинты `/setup-preauth` позволяли перезаписать чужую 2FA зная только пароль, а в Google Auth отсутствовала проверка обязательной 2FA для администратора.
- **Цель**: Комплексно укрепить безопасность 2FA, добавить защиту от несанкционированной настройки/сброса, лимитировать попытки ввода кода настройки, аннулировать сессии при настройке и реализовать чистый UI первичной настройки на фронтенде с поддержкой 4 локалей.

### 2. Реализованные изменения

#### А. Укрепление бэкенда (`TwoFactorService`, `TwoFactorController`, `GoogleAuthService`, `AuthResponse`)
1. **Разграничение контракта в `AuthResponse`**:
   - `requires2FA(preAuthToken)`: возвращает `twoFactorEnabled = true` (указывает клиенту запросить 6-значный код TOTP).
   - `requires2FASetup(preAuthToken)`: возвращает `twoFactorEnabled = false` (указывает клиенту показать QR-код и форму первичной настройки).
2. **Защита от перезаписи 2FA**:
   - В `TwoFactorService.getUserForPreAuthSetup` и `confirmSetupWithPreAuth` добавлена строгая проверка: если `user.isTwoFactorEnabled() == true`, запрос немедленно отклоняется (`BadRequestException: Двухфакторная аутентификация уже настроена`).
   - В `confirmSetup` (включая вызовы из профиля) запрещена перезапись активной 2FA без предварительного подтверждённого отключения через `disable2FA`.
3. **Защита от брутфорса при настройке**:
   - В `confirmSetupWithPreAuth` внедрен контроль попыток (максимум 5). При превышении токен удаляется, сессия сбрасывается.
4. **Инвалидация сессий при настройке**:
   - При успешном завершении первичной настройки 2FA вызывается `refreshTokenService.revokeAll(user)` для сброса всех потенциально скомпрометированных старых сессий.
5. **Закрытие обхода через Google OAuth (`GoogleAuthService`)**:
   - Для пользователей с ролью `ADMIN` без настроенной 2FA вход через Google теперь возвращает `requires2FASetup` вместо прямой выдачи токенов.

#### Б. Фронтенд (`TotpSetupForm`, `LoginPage`, `AuthContext`, `authApi`, локализация)
1. **Новый компонент `TotpSetupForm.tsx`**:
   - Показ QR-кода и секретного ключа для ручного ввода через эндпоинт `/api/v1/auth/2fa/setup-preauth`.
   - Кнопка быстрого копирования секретного ключа.
   - 6-значный ввод кода и подтверждение через `/api/v1/auth/2fa/setup-preauth/confirm`.
2. **Маршрутизация шагов в `LoginPage.tsx`**:
   - Добавлен шаг `TOTP_SETUP`.
   - Если сервер вернул `requires2FA` с `twoFactorEnabled === false`, отображается `TotpSetupForm` вместо `TotpVerifyForm`.
3. **API клиент (`authApi.ts`)**:
   - Добавлены функции `get2FASetupPreAuth` и `confirm2FASetupPreAuth`.
4. **Локализация (i18n)**:
   - Добавлены ключи `totpSetup.*` для всех 4 языков (`ru`, `kk`, `en`, `zh`).
